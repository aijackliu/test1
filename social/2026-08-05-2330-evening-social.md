### GitHub

10. **cloudflare/computer**
   - **主題：Give your agent a computer**
   - **摘要：** Cloudflare 的新熱門 repo 把「agent 有一台電腦」具體化成虛擬檔案系統與多種 execution backend，包含 container、isolate shell、isolate JavaScript。核心是把執行環境做成可插拔、可持久的 workspace。
   - **連結：** https://github.com/cloudflare/computer
   - **為何值得看：** 這類 infra 很可能變成未來 agent runtime 的標配抽象層。

11. **huangruiteng/loopx**
   - **主題：長任務 agent 的本地 control plane**
   - **摘要：** LoopX 主打 long-running AI agent work，強調 objectives、gates、todos、evidence、handoffs 的穩定狀態管理，且不綁單一 agent runtime。它不是再造模型，而是在補 agent 工作流最痛的可追蹤性。
   - **連結：** https://github.com/huangruiteng/loopx
   - **為何值得看：** 如果你關心多 agent 協作、可復盤與人類審核，這是很對位的方向。

12. **TencentCloud/TencentDB-Agent-Memory**
   - **主題：team-level memory hub for AI Agents**
   - **摘要：** Tencent 把 conversations、docs、code 轉成四種可重用記憶資產：Chat Memory、Skill、LLM-Wiki、Code-Graph，並強調 governed / shared / equipped。這是把「記憶」從單對話能力拉高到團隊級基礎設施。
   - **連結：** https://github.com/TencentCloud/TencentDB-Agent-Memory
   - **為何值得看：** agent 走進團隊與企業環境後，記憶治理會比單次回答更重要。

13. **firecrawl/pdf-inspector**
   - **主題：快速判別 PDF 是否需要 OCR**
   - **摘要：** 這個 Rust library 主打先分類 PDF（text-based / scanned / mixed），再做位置感知文字抽取與 Markdown 轉換，避免不必要 OCR。Firecrawl 直接把文件 ingestion 的成本與路由問題產品化了。
   - **連結：** https://github.com/firecrawl/pdf-inspector
   - **為何值得看：** 文件處理是 agent workflow 的高頻入口，能先省 OCR 就是在省錢、省延遲。
